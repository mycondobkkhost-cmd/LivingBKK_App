# สมุดโครงการมาสเตอร์ (ภาษาบ้านๆ)

**อัปเดต:** 2026-07-27

## สรุปหนึ่งประโยค

**ชื่อโครงการ** ยึดจาก **Property Hub**  
**ทำเล + รถไฟฟ้า** ประกอบจาก **Property Hub + LivingInsider**  
ของจาก Pantip ใช้ได้แค่ช่วยค้น (ชื่อเล่น) — **ไม่ใช่สมุดชื่อหลัก**

---

## ทำไมรอบ Pantip ถึงงง

รอบก่อนดึงรายชื่อจาก Pantip มาใส่สมุด (~2,000 ชื่อ)  
ปัญหา: ชื่อซ้ำ/เพี้ยน, พิกัดหลายอันเป็นแค่ “ใกล้สถานี” ไม่ใช่หมุดอาคารจริง  
เลยอ่านแล้วรู้สึกว่าข้อมูลเยอะแต่ยังพึ่งไม่ได้ — **ถูกแล้วที่รู้สึกอย่างนั้น**

ทางที่ถูกต้องของโปรเจกตนี้มีอยู่แล้วในคู่มือ:

- `docs/คู่มือ-Property-Hub-เว็บเดียว.md`
- `docs/คู่มือ-รวบรวมโครงการ-ทางA.md`

## ใครเป็นเจ้านายข้อมูลอะไร

| ข้อมูล | แหล่งหลัก | แหล่งเสริม |
|--------|-----------|------------|
| ชื่อไทย / อังกฤษ / slug | **Property Hub** | — |
| พิกัดหมุดอาคาร | **Property Hub** | LivingInsider เติมเมื่อ PH ว่าง |
| เขต / ทำเล | **Property Hub** | LivingInsider เติมเมื่อว่าง |
| BTS/MRT ใกล้ | คำนวณจากพิกัดจริง + ข้อความจาก PH/LI | รวมกัน ไม่ให้ชื่อสถานีไปปน aliases |
| ชื่อเล่น (ค้นหาเจอ) | PH aliases | LI ชื่อที่สะกดต่าง / (ออปชัน) Pantip |

## วิธีสร้างสมุดในแอป (ลำดับที่ถูก)

```bash
source scripts/dev-path.sh
./scripts/deploy-projects-cloud.sh

# มีรายการ slug กทม.+ปริมณฑล ~2,700 แล้วใน data/ph-pipeline/
SKIP_DISCOVER=1 ./scripts/sync-propertyhub-cloud.sh

# จัด BTS/MRT จากพิกัดจริง (ล้างสถานีที่ปนผิด)
python3 scripts/rebuild-project-transit-links.py
```

หรือในแอปแอดมิน → แท็บ **โครงการ** → **ดึงทั้งหมดจาก Property Hub**

จากนั้นถ้าต้องการเติมพิกัดจาก LivingInsider: วางลิงก์หน้าโครงการ LI ในแอดมิน  
ระบบจะ **ไม่ทับชื่อ Property Hub** — เติมแค่พิกัด/ทำเล/รถไฟฟ้าที่ยังว่าง และเก็บชื่อ LI เป็น alias

สคริปต์รวม: `./scripts/build-project-master.sh`

## สิ่งที่แอปเห็น

ตาราง `property_projects` → `ProjectCatalog` → ช่องเลือกโครงการตอนลงประกาศ

`source_platform = propertyhub` = แถวมาสเตอร์ชื่อที่ไว้ใจได้
